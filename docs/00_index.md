# マリオピクセル — ゲームロジック仕様書 (Web 事前調査版)

本ドキュメント群は、Web (PC/スマホ クロスデバイス) で動作する「マリオ系ピクセルアート 2D サイドスクロール プラットフォーマー」(コード名: **マリオピクセル**) の実装に先立ち、ゲームロジックを体系化したものである。

## 位置付け

- **目的**: ウェブアプリ開発の事前調査。実装フェーズで参照する単一の真実 (single source of truth)。
- **対象範囲**: ゲームプレイのロジック (物理、衝突、敵、アイテム、状態管理) と、ロジックを支える Web 基盤 (描画、入力、レスポンシブ、保存) の両方。
- **アート/演出/ナラティブ**: 範囲外。別途資料化する。
- **マルチプレイ**: 範囲外 (シングルプレイヤー前提)。将来拡張は §94 アーキテクチャに含む。

## 用語

- **px**: 論理ピクセル (内部仮想解像度上の単位)。本作の基準内部解像度は **16 px = 1 タイル**, **256×240 px** (NES 比) または **480×270 px** (16:9 拡張) を初期候補とする。最終決定は §97 で扱う。
- **subpixel**: 内部小数表現。本作では `1 px = 16 subpixel` (SMB1 互換, 4 ビット小数) を採用する [SMBpedia/SDA Knowledge Base 由来]。
- **frame**: 物理ステップ。固定タイムステップ **60 Hz (1/60 s)** を基準とする (§94)。
- **tile**: ステージ構造の最小単位。**16×16 px** の方眼。
- **screen**: 描画される論理画面 (例: 256×240 px)。物理画面 (デバイス) とは独立。
- **player**: プレイヤーキャラクター。本書では "Mario" に相当する役割名。固有名は別途。

## 設計原則

1. **決定論優先** — 同じ入力列・同じシードからは常に同じ結果を得る。テストとリプレイのため。
2. **クロスデバイス第一** — 入力は抽象化、解像度は仮想化、性能はモバイル基準で設計。PC は性能上限が高い側として扱う。
3. **整数物理 + サブピクセル** — 浮動小数の累積誤差を避け、SMB1 系の挙動を再現可能にする。
4. **古典の挙動を体感的に踏襲、QoL は現代化** — 物理パラメータは古典準拠で再現性高く、入力受付 (coyote/buffer) や a11y は現代基準で底上げする。
5. **データ駆動** — ステージ、敵、アイテムは JSON 等のデータで定義。ロジックはデータを解釈する側に留める。
