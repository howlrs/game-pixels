# 98. ピクセル概念の現代/次世代化

## 18.1 視点

「ピクセルアート 2D プラットフォーマー」は、**視覚的な硬質さ** と **古典的な物理感覚** の二要素で構成される。本書では両者を **分離可能** にし、それぞれに「古典/現代/次世代」モードを設ける。

## 18.2 二軸の設計

### 18.2.1 物理 (内部) は古典

- 物理は §20 の SMB1 互換 (整数 + subpixel)。
- 60Hz 固定。決定論。
- 体感の "Mario フィール" を保つ。

### 18.2.2 視覚 (外部) は段階選択

| モード | 表示の原則 |
|---|---|
| **クラシック** | nearest-neighbor、整数倍スケール、subpixel 位置を `>> 4` で px 整数化、シェーダ無し。古典 NES 風。 |
| **モダン** | nearest-neighbor を維持しつつ、subpixel 位置を **そのまま反映** (skipping the `>> 4` rounding)。120Hz/144Hz で滑らか。 |
| **HD-2D 風** | 高解像度バックグラウンド + Bloom + 加算光源 (コイン、ファイア)、ピクセル化されたキャラクタは保持。 |
| **CRT** | scanline + barrel distortion + 残光 (フェードフレーム平均)。WebGL/WebGPU 必須。 |

### 18.2.3 物理と視覚の独立性

- いずれの視覚モードでも物理は同一。同じ入力列で同じ frame の終了状態に到達する。
- 視覚モードはスコア/タイム/到達点に**絶対に影響しない**。

## 18.3 サブピクセルモーション (詳細)

- 古典 NES では "16 subpixel = 1 pixel" の整数演算で、表示時に `>> 4` で 1 px 単位で動く。これが「ぴょこぴょこした不連続」を生む。
- 本作の「モダン」モードは、表示時に subpixel をそのまま `(x_sub / 16) * scale` で実数座標にして描画 (ただし draw 時は `Math.round` を経由してピクセル境界に着く)。
- 究極的には WebGPU 使用時に **vertex で実数座標 + fragment で nearest sampling** にすれば「ぼやけずに滑らかに動くドット絵」が表現できる。

## 18.4 解像度の現代化

- 内部解像度は **16:9 で 480×270 px** を主軸とする (§17)。これは NES 解像度のおよそ 2 倍 (面積で 2 倍強)、ピクセルあたりの情報量を倍に。
- 結果: 「広い視野」「複数敵の同時可視化」が可能。古典の窮屈さを軽減しつつ、ドット感は維持できる。

## 18.5 ライト & シェーディング (HD-2D 風)

- **ボリューメトリックフォグ層**: 背景に薄いグラデーション層を追加。プレイヤー前面はクリア、奥は色温度を低く。
- **ポイントライト**: コイン、ファイア弾、Star に半径付き加算光源 (Canvas2D の `globalCompositeOperation = 'lighter'` でも実現可能)。
- **ピクセル境界の保持**: シェーダはピクセル境界を超えて滲ませない (Bloom は別レイヤで合成)。

## 18.6 アニメーション現代化

- 古典: 各キャラ 2〜4 frame ループ。
- 本作: 4〜6 frame の二段階補間アニメ (例: ジャンプの予備動作 1 frame、上昇 1 frame、頂点 1 frame、下降 2 frame, 着地 1 frame)。
- 「踏みつぶし時の伸び」「ダメージ時の歪み」は **リアルタイム頂点歪み** で表現 (Canvas2D では transform、WebGPU では vertex shader)。

## 18.7 パーティクル

- 古典の "破片 4 個" を拡張。土埃、葉、火花を **ECS なしの軽量プール** で実装。ステージ環境ごとに別パレット。

## 18.8 次世代要素 (将来)

- **AI による背景生成**: ステージ JSON のテーマから背景レイヤをランタイム生成 (Stable Diffusion 系の事前生成済みアセットを動的合成)。
- **音声プロシージャル**: 環境音 (風、水) を Web Audio の合成で生成、ループ感を低減。
- **アクセシビリティ AI**: スクリーンリーダー向けにステージのテキスト要約を自動生成。
- これらは MVP 範囲外。

## 18.9 「ピクセルパーフェクト」と "解像度自由"

- ユーザー側で **ピクセル解像度を変える** (例: 1px = 1物理ピクセル / 1px = 4物理ピクセル) スライダーを提供。
- 解像度を変えても物理は不変、UI のヒット領域は別に確保。
