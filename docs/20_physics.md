# 20. 物理モデル

## 2.1 単位系

- 内部単位: **subpixel** (`1 px = 16 subpixel` = `1 << 4`)。
- 速度: `subpixel / frame`。表示時に `>> 4` で px に丸める (整数算術で決定論を保つ)。
- 加速度: `subpixel / frame^2`。
- 物理ステップ: **60 Hz 固定** (`dt = 1/60 s`)。可変フレームレートでも論理は固定タイムステップで進める (§94)。
- 浮動小数は使わない (内部状態は 32 bit 整数)。レンダリング側でのみ補間目的に小数を扱う (§91)。
- JavaScript/TypeScript ではすべての数値が IEEE754 倍精度浮動小数で表現される。決定論を確保するため、物理計算の終端で `(x | 0)` の整数化を徹底する。あるいは `Int32Array` の TypedArray を採用してアクター状態を SoA (Struct-of-Arrays) で保持する (§94 を参照)。

## 2.2 キャラクタ運動 (プレイヤー基準)

### 2.2.1 水平運動

| 状態 | 値 (subpixel/frame) | 備考 |
|---|---|---|
| 走り (run) 速度 上限 | **±40** | A ボタン (Run) を保持中の上限。約 2.5 px/frame ≒ 150 px/sec。 |
| 歩き (walk) 速度 上限 | **±24** | Run 非保持時の上限。比率はおよそ 3:5。 |
| 加速 (進行方向に押している) | 既定: フレーム毎に subspeed 累積 → 速度+1 | 詳細は §2.2.2 を参照。 |
| 加速 (逆方向, スキッド) | 進行方向と入力方向が逆 → 加速倍率 約2倍 | SMB1 disassembly 由来 [SMBpedia]。 |
| 摩擦 (入力なし、地上) | 配列ベース減衰 `[0xe4, 0x98, 0xd0]` を低速/中速/高速で参照 | 速度が遅くなるほど減衰が緩やか。 |
| 空中減速 | 入力に応じて加速のみ。摩擦は 0。 | 最高速度の維持: 空中では摩擦が効かない。 |

> 出典: SMB1 disassembly (SMBpedia, simplistic6502)。`Player_X_Speed` (subpixel/frame), `Player_X_MoveForce` (subspeed: 加速計算専用で位置には影響しない) の二段構成。

### 2.2.2 加速の二段構造 (SMB1 互換)

```
# 1 フレーム毎
Player_X_MoveForce += accel_for_state    # subspeed (累積)
if Player_X_MoveForce overflows 1 px:
    Player_X_Speed += sign(input) * 1
    Player_X_MoveForce -= 16             # キャリーアウト
clamp(Player_X_Speed, -cap, +cap)
```

これにより低速域はカクつかず、線形でないスムーズな加速が得られる。整数のみで計算可能。

### 2.2.3 垂直運動

| 状態 | 値 (subpixel/frame) | 備考 |
|---|---|---|
| ジャンプ初速 (静止/低速) | `-0x40 (-64) subpixel/frame` 程度を起点 | SMB1 の `Initial speed` 配列 `[0xfc, 0xfc, 0xfc, 0xfb, 0xfb, 0xfe, 0xff]` (8 bit 符号付き) は `−4` 〜 `−5` 相当の値で、これを subpixel 単位の `Player_Y_Speed` に格納する (例: `−4 << 4 = −64`)。speed_idx により水平速度に応じて変化。 |
| 重力 (ボタン保持中) | 配列 `JumpForce[Mario]: [0x20, 0x20, 0x1e, 0x28, 0x28, 0x0d, 0x04]` をテーブル参照 | 水平速度に応じて変化。低い値 = 高く飛ぶ。 |
| 重力 (ボタン解放後) | 配列 `FallForce[Mario]: [0x70, 0x70, 0x60, 0x90, 0x90, 0x0a, 0x09]` | 大きい値 = 速く落ちる。 |
| 終速 (terminal velocity) | 約 `+4.0 px/frame` (`+64 subpixel/frame` 程度) | 床のすり抜け抑止のため必須。 |
| 水中 重力 | `+0x18` (定数) | §2.4。 |
| 画面遷移時 重力 | `+0x28` (定数) | カメラ追従外の落下用。 |

> 重力テーブルのインデックスは「水平速度の階層」(0〜6) で選ぶ。SMB1 の "走るほど高く飛べる" が再現される。

### 2.2.4 可変ジャンプ高 (Variable Jump Height)

実装方式: **二重重力**。

```
if jump_button_held && vy < 0:
    vy += JumpForce[speed_idx]
else:
    vy += FallForce[speed_idx]
clamp(vy, -∞, terminal_velocity)
```

- ジャンプボタンを離した瞬間以降は `FallForce` (大) を使う。これで「短く押す = 低い跳躍」「押し続ける = 高い跳躍」が成立する。
- 水平速度が高いほど `JumpForce[i]` が小さい (= 引力が弱い) ため、走り中ほど高く・遠く飛べる。

### 2.2.5 SOCD (左右同時入力) の扱い

PC のキーボードや一部のレバーレスコントローラでは、Left/Right の同時入力が容易に発生する。本作の既定動作:

- **既定: "後押し優先" (last input wins)** — 直近に押されたほうを採用、もう一方は離されるまで無効。SOCD 解消の現代標準。
- オプション: "neutral" (両方押下中は入力なし扱い) を a11y 設定 (§96) に置く。
- 古典の「rapid skid」(L+R で `Player_X_MoveForce` を倍速減衰) は **無効** を既定とし、希望者向けの "クラシック SOCD" モードとしてのみ提供する (§4.7)。

### 2.2.6 入力受付の現代化 (QoL)

古典 SMB1 にはないが、本作で **明示的に追加** する:

| 機能 | 値 | 説明 |
|---|---|---|
| Coyote Time | **6 frames (≒100ms)** | 地面を離れて落下中でも、6 フレーム以内ならジャンプ受付。 |
| Jump Buffer | **6 frames (≒100ms)** | 着地前にジャンプ入力された場合、着地後 6 フレーム以内なら自動消化。 |
| Edge forgiveness | **±2 px** | 端ギリギリの判定を 2 px だけ寛容にする (足場踏み外し対策)。 |

採用根拠: Celeste 等で確立された "game feel" 強化の標準パターン。古典の挙動を壊さず体感の不快感だけ取り除く。

## 2.3 衝突応答 (物理側からの要件)

詳細は §30 で扱う。物理側の API 要件:

- 軸分離 (X 移動 → 衝突解決 → Y 移動 → 衝突解決) を前提に、`vx`, `vy` は独立に書き換えられる。
- 接地フラグ (`on_ground`) は Y 衝突解決時に立てる。崖から踏み出した時にだけ `coyote_timer` を起動する。
- 天井ヒット (頭打ち) で `vy` を 0 に丸め、ジャンプを打ち切る (`jump_button_consumed = true`)。
- 壁ヒットで `vx` を 0 に丸める。subspeed もリセットして再加速をやり直す (古典挙動)。

## 2.4 環境物理

| 環境 | 重力 | 水平速度上限 | 備考 |
|---|---|---|---|
| 通常 | §2.2.3 | ±40 (run), ±24 (walk) | 既定。 |
| 水中 | `+0x18`/frame | ±24 (run), ±16 (walk) | ジャンプボタン = 泳ぐ (連打で上昇)。終速も低い。 |
| 氷面 | 既定 | ±40 | 摩擦テーブルを `[0xfc, 0xfc, 0xfe]` 等の "ほぼ無摩擦" に差し替え (実装で可変)。 |
| ベルトコンベア | 既定 | ±40 | 接地時に `vx` に固定値を加算 (床側のプロパティ)。 |
| バネ (spring) | 反力 -0x70 | — | 接地検知後 1 frame で `vy = -0x70` を強制。A 保持で更に高く (-0x60)。 |

## 2.5 「ピクセル概念」の現代化との整合 (要約)

- §98 で詳述するが、**論理物理は SMB1 の整数 + subpixel を維持**しつつ、描画側で "サブピクセル位置をそのまま線形補間で見せる" モードを選択肢にする。
- これにより「カクつかない滑らかな現代的見栄え」と「ドット絵としての硬質さ」を切替可能にする。物理は決定論を保つ。

## 2.6 数値の出典と注意

- 上記 SMB1 系の数値は SMBpedia (simplistic6502 によるドキュメント化) を一次参照とした。原典は SMB1 NES 6502 disassembly (doppelganger 版 等)。
- 速度配列・摩擦配列の値は **本作の最初の調整起点** であり、Web のクロスデバイス UX に合わせて再調整する。
- 60Hz 固定で設計するため、120Hz/144Hz ディスプレイでは **論理は 60Hz、描画は補間** で対応する (§91)。
