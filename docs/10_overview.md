# 10. プロダクト概要

## 1.1 ジャンルと参照点

- **ジャンル**: 2D サイドスクロール プラットフォーマー (アクション)。
- **明示的参照**: SMB1 (NES, 1985)、SMB3 (NES, 1988) の運動感覚と物理パラメータを設計の出発点とする。
- **暗黙の参照**: Celeste (2018) の入力受付 (coyote time / jump buffer)、現代的アクセシビリティ。
- **意図的な非参照**: 3D プラットフォーマー、メトロイドヴァニア (バックトラックを前提にしない)、ローグライト的ランダム生成。

## 1.2 ゴール (プレイヤー視点)

- **ステージゴール**: ステージ右端 (またはゴール建造物) に到達する。
- **ワールドゴール**: 連続するステージを順番にクリアする。
- **隠し要素**: 隠しアイテム、ショートカット、コイン全回収などの副ゴール (任意)。

## 1.3 失敗条件と継続

- **死亡**: 体力消失、画面下落下、時間切れ。死亡するとライフを 1 消費し、直前のチェックポイント (なければステージ開始位置) からリトライ。
- **ゲームオーバー**: ライフが尽きると、ワールドの開始ステージに戻る。クラウド系のセーブは §93 で扱う。

## 1.4 セッション粒度

- 1 ステージ = 60〜180 秒程度を目安。短いセッションでクリア可能なように設計する。
- スマホでの「電車内・スキマ時間プレイ」を想定した UX を §97 で扱う。

## 1.5 設計上の制約 (Web ならでは)

| 制約 | 設計方針 |
|---|---|
| ブラウザ自動再生制限 | 初回ユーザー操作 (タップ/キー入力) で AudioContext を resume する (§92)。 |
| タブ非アクティブ時 RAF 停止 | 復帰時にデルタタイムを上限クリップしてスパイラルデス防止 (§94)。 |
| 端末性能のばらつき | 描画コストを fallback (シェーダ無し → Canvas2D) で段階的に下げる (§91, §95)。 |
| ネットワーク不安定 | 静的アセットは PWA precache、進捗は IndexedDB に保存 (§93)。 |
| 操作系の差異 | キーボード/マウス、タッチ、ゲームパッド、3 系統を完全対応 (§90)。 |

## 1.6 範囲外の明示

- マルチプレイ (協力/対戦)、ユーザー生成コンテンツ (Mario Maker 系) は MVP 範囲外。アーキテクチャ上は将来拡張可能性を残す (§94)。
- 課金/広告 SDK は範囲外。ただし IndexedDB を抽象化して将来差し替え可能にしておく (§93)。
